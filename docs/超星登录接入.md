# 超星登录接入

金工平台复用已有的超星认证中心。学生前往认证中心登录，认证中心返回一次性票据，金工平台的 Supabase Edge Function 验票后建立本项目的 Supabase 会话。问卷与反馈继续按该会话的账号归属保存。

用户已确认认证中心为 `https://sdtqvk3ybm.coze.site`，金工站点为 `https://app-hcpuq0il7wlp.cxiagents.com/`。认证中心的回跳白名单应加入精确 origin `https://app-hcpuq0il7wlp.cxiagents.com`，本地调试还需要 `http://127.0.0.1:4173`。

2026-11-17 检查发现，认证中心的 `/logout` 返回 404，实际退出入口为 `/api/auth/logout`。使用未登录的独立 HTTP 请求访问退出接口时，目标站点回跳被转到中心根路径，尚未确认该站点已加入白名单。管理员应在中心后台核对，而非据此认定登录成功。

## 认证中心接口

当前接入依据本机“超星登录认证系统”的已实现协议。

- `GET /api/auth/chaoxing?return_to=...` 发起认证。认证中心会在回跳地址追加 `ticket`，并保留原有查询参数。
- `POST /api/sso/verify` 接收 JSON `{ticket,secret}`，成功返回已验证身份，至少包含 `uid` 和 `fid`。
- 票据由认证中心签发，有效期 120 秒且只能使用一次。

本项目不会根据浏览器提供的姓名、学号或角色直接建立登录。管理员用认证中心确认的 `fid + uid` 绑定已有课程账号。姓名或学工号用于人工核对，绑定主键使用超星 UID。

## Supabase 配置

1. 先执行既有 `20261109000100_course_evidence.sql`，再执行 `20261117000100_chaoxing_login.sql`。
2. 在 Authentication → Users 创建课程账号，并在 `metalwork_profiles` 分配姓名、班级及学生或教师角色。已有课程账号继续使用原 UUID，可保留该账号已有云端数据。
3. 管理员核实超星 FID、UID 与课程账号后，执行绑定。下列内容须替换成实际身份。

   ```sql
   insert into public.metalwork_chaoxing_accounts (fid, uid, user_id)
   values ('学校FID', '超星UID', '00000000-0000-0000-0000-000000000001');
   ```

4. 在 Supabase Edge Function 的 Secrets 中配置以下变量。只填在服务端，不能使用 `VITE_` 前缀。

   | 变量 | 内容 |
   | --- | --- |
   | `CHAOXING_SSO_BASE_URL` | `https://sdtqvk3ybm.coze.site` |
   | `CHAOXING_SSO_SHARED_SECRET` | 与认证中心 `SSO_SHARED_SECRET` 一致的验票密钥，至少 16 个字符 |
   | `CHAOXING_ALLOWED_ORIGINS` | `https://app-hcpuq0il7wlp.cxiagents.com,http://127.0.0.1:4173`；仅保留实际启用的站点 |
   | `CHAOXING_ALLOWED_FIDS` | 允许学校的 FID，多个用逗号分隔 |

   Edge Function 使用 Supabase 提供的 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` 和 `SUPABASE_ANON_KEY` 建立本项目会话。服务角色密钥只存在于函数运行环境。

5. 部署 `chaoxing-auth` Edge Function。仓库中的 `supabase/config.toml` 为此登录入口设置 `verify_jwt = false`，因为用户开始登录时尚无会话。函数自行验证访问源、浏览器登录凭据、一次性票据和管理员绑定名单。

   ```sh
   supabase functions deploy chaoxing-auth --project-ref 项目ID
   ```

6. 在已有认证中心后台的回跳白名单中加入金工平台的访问源，机构白名单也应包含对应学校。预览域名、本机地址和正式域名需要各自配置，填写当前实际使用的地址。

## 前端构建配置

部署平台配置以下构建环境变量，再重新构建并发布 `dist/client`。

| 变量 | 内容 |
| --- | --- |
| `VITE_SUPABASE_URL` | 当前项目的 Supabase URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | 当前项目的 publishable key 或旧版 anon key |
| `VITE_CHAOXING_LOGIN` | `true` |

启用后，登录页提供“超星账号登录”，并保留课程邮箱登录入口。登录后从服务器的 `metalwork_profiles` 读取课程角色和班级。未绑定的超星身份会提示联系管理员。

超星账号不直接合并旧版浏览器演示记录。旧版云端账号要继续保留数据时，将超星身份绑定到该账号的 UUID。

## 登录验证

- 已绑定学生完成真实超星认证后能进入课程，同一账号换浏览器登录能读回问卷。
- 同班教师能查看所属班级，其他班级不可见。
- 未绑定身份、非允许学校、过期或已使用票据应拒绝登录。
- 登录回跳地址中的票据会立即清除。换标签页、缺少本次登录凭据或重复回跳时，需要重新发起登录。
- 退出金工平台后，会顶层跳转至认证中心 `/api/auth/logout?return_to=...` 清除中心会话，再回到本站。中心退出失败会保留重试入口。中心代码没有调用上游超星的退出接口，超星已有的授权状态仍可能让下次认证自动完成。

本地模拟接口测试与真实超星登录验收分别记录。完成认证中心地址、密钥、名单和函数部署后，才能执行线上端到端验证。

## 现有部署平台副本的差异

NoahCoder 中的金工项目已额外适配平台数据库客户端和租户请求头。该副本的配置、表结构与本仓库独立 Supabase 项目方案存在差异。接入时需保留已有平台适配，先确认平台是否支持部署 Edge Function 或提供服务端验票及会话签发入口。

平台副本还报告过用户自行选择教师角色的建档流程。接入超星时应将课程角色和班级改由可信名单或服务端审核分配，避免把前端选择当作教师权限依据。部署时应检查实际代码和权限规则。
